### 关键坑（重要）
- FastHTML 路由若直接 `return` 一个 Python list/dict 列表，在“直接 ASGI 调用”（静态构建脚本）下**不会**自动序列化为 JSON，会回落到默认页；线上 uvicorn 也可能表现不一致。修复：显式 `return JSONResponse(data)`（from starlette.responses）。
- 冒烟测试 `must_contain=["title"]` 会假阳性命中默认页 `<title>` 标签；校验 JSON 端点应解析 body 并确认结构。
- apsw 游标无 `.description` 属性，取列名用 `cur.getdescription()`；本项目已封装 `_rows()` 统一处理。
- `.sesskey` 是 FastHTML 启动生成的会话密钥，属运行时产物，已加入 `.gitignore`。

- 现象：用户改 .env 的 ADMIN_TOKEN（新值含 %/$ 特殊字符）并重启后，新密码登录失败、旧密码 123456 反而能登录。
- 排查：① dotenv 实测解析 .env 无误（无 BOM、$ 未被吃，值=QSsnb7%M$*mM9nxk 与文件一致）→ 配置本身没问题；② curl 分别用新旧密码 POST /admin/login：新密码 200(失败)、旧密码 303(成功) → 服务器内存认旧值；③ netstat 发现 5000 端口被 PID 7668 与 25816 **两个进程同时 LISTENING**（Windows 双绑定），.env 15:40 修改、旧进程 25816 14:32 启动 → 请求打到内存里仍是旧 .env/旧代码的进程。
- 教训（反复出现）：uvicorn reload 只杀父进程会残留 worker，旧实例不死、新实例又起 → 双绑 5000，请求被旧进程接住 → "改了密码/代码不生效"的假象。此前分页不显示、/posts/ 重定向不生效同根因。
- 处置：需用户彻底结束全部残留 python.exe（任务管理器或 `wmic process where "name='python.exe'" call terminate`），确认 netstat 无 5000 LISTENING 后只启动一个 python main.py。

### 补充：热更新答疑 + 一键重启脚本
- 用户问「你都不支持热更新吗」。确认：serve() 用 uvicorn.run(reload=DEBUG)，DEBUG=1 → 热更新本就开启（blog/__init__.py:72）。
- 热更新管不到的两类情况（用户全部踩中）：
  1. 改 `.env`（ADMIN_TOKEN/SECRET_KEY 等）→ uvicorn reloader 默认只监视 .py 文件，不监视 .env，改配置必须重启进程，这是设计而非失效。
  2. 僵尸进程占端口：15:43 实测 5000 仅剩 PID 25816（14:32 启动的老进程，reloader 已卡死）在监听 → 请求全被旧进程接住，代码改了热更也到不了浏览器。
- 新增 `restart-dev.bat`（项目根目录，ASCII 内容）：choice 确认 → 按 5000 端口 PID 逐个 taskkill + taskkill /IM python.exe → cd 到脚本目录 → python main.py。用户双击即可获得「干净的单进程服务器」，此后改 .py 自动热更秒级生效；改 .env 后跑一次该脚本。
