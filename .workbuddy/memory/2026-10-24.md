## 用户反馈"颜色根本没变，还是深红色" → 根因=缓存 + 写死版本号
- 核验：源文件/5001服务/build 三处 accent 早已是天青 `#3f9688`（无红色残留）。用户看到的红是**浏览器缓存的旧 CSS**。
- 真正根因：上一轮加的 `?v=2` 是**写死**的，后来两次改色（天蓝→汝窑天青）URL 没变，浏览器一直用缓存的红色 `?v=2`；且 5000 旧进程用无版本号引用，更易命中更早的红色缓存。
- 根治：`blog/__init__.py` 增加 `_asset_ver(rel)` 用**文件修改时间**作为版本号（CSS/JS 一改 URL 自动变，永久破缓存）。三处引用改 `?v={_asset_ver(...)}`。
- 旧进程困局：5000(main.py)、5001(uvicorn --reload 未接管 `__init__.py` 顶层改动)在沙箱内均无法终止；新起 **5002** 端口全新 uvicorn（`python -m uvicorn blog:app --port 5002 --reload`）验证 200 + 引用 `?v=1792822663`(mtime) + CSS 天青。
- 提交 `c5b0338`「fix: auto-version static assets by mtime to bust browser cache」，推送 `9911371..c5b0338`。（注：第一次 commit 后 push 因管道 PIPESTATUS 误判未实际执行，已单独补 push 成功。）
- 教训：**改静态资源内容时版本号必须跟着变**；写死 `?v=N` 会重复踩坑。自动 mtime 版本号一劳永逸。
